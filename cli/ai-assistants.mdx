Use the CLI with an AI coding assistant to manage NeetoPlaydash in plain language. The `neetoplaydash setup` commands add NeetoPlaydash instructions for your assistant, while [`--toon`](/cli/output-formats) keeps command output compact for it to read.

## Set up your assistant

Run the subcommand for the tool you use:

| Command | What it does |
| --- | --- |
| `neetoplaydash setup claude` | Extracts the NeetoPlaydash plugin (manifest, marketplace, session-start hook, and skill) to `~/.config/neetoplaydash/claude-plugin`, replacing any earlier copy. Requires `~/.claude/` to exist. |
| `neetoplaydash setup cursor` | Writes `.cursor/rules/neetoplaydash.mdc`. Overwrites the file. |
| `neetoplaydash setup windsurf` | Writes `.windsurf/rules/neetoplaydash.md`. Overwrites the file. |
| `neetoplaydash setup copilot` | Adds a NeetoPlaydash section to `.github/copilot-instructions.md`. Keeps the rest of the file. |
| `neetoplaydash setup gemini` | Adds a NeetoPlaydash section to `GEMINI.md`. Keeps the rest of the file. |
| `neetoplaydash setup codex` | Adds a NeetoPlaydash section to `AGENTS.md`. Keeps the rest of the file. |

Every subcommand except `setup claude` writes into the current directory, so run it from the root of the project the assistant works in. The `copilot`, `gemini`, and `codex` commands place their section between `<!-- neetoplaydash:start -->` and `<!-- neetoplaydash:end -->` markers and replace that section on re-run instead of adding a duplicate. Re-run the command after every CLI upgrade so the instructions match the installed version.

```bash
neetoplaydash setup claude
```

`setup claude` prints two slash commands to finish the installation inside Claude Code:

```text
/plugin marketplace add ~/.config/neetoplaydash/claude-plugin
/plugin install neetoplaydash@neetoplaydash
```

After setup, your assistant can check the commands and flags available in your installed CLI version:

```bash
neetoplaydash commands
```

The command prints the complete catalog as JSON.

## Tips for agent workflows

<Tip>
  Prefer `--toon` when the assistant needs to read a list or record, and
  `--quiet` when it needs to pipe an identifier into the next command. See
  [Output formats](/cli/output-formats).
</Tip>

- Authenticate once with [`neetoplaydash login`](/cli/authentication); the assistant reuses the stored credentials.
- When several workspaces are signed in, the assistant must pass `--subdomain <name>` on each command.
- Run [`neetoplaydash doctor`](/cli/troubleshooting) first to confirm the assistant is authenticated and connected.
