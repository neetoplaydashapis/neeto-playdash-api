## Run the doctor

When something goes wrong, start with `neetoplaydash doctor`. It checks your authentication, API connection, and CLI version.

```bash
neetoplaydash doctor
```

When multiple workspaces are signed in, name the one to check:

```bash
neetoplaydash doctor --subdomain your-workspace
```

## Common errors

When a command fails, it prints an error message to standard error and exits with status 1. Usage errors such as an unknown flag or a missing argument add `Run 'neetoplaydash --help' for usage.`

<AccordionGroup>
  <Accordion title="Not authenticated. Run 'neetoplaydash login' to authenticate.">
    **Problem**: no workspace is signed in. <br />
    **Solution**: run [`neetoplaydash login --subdomain <name>`](/cli/authentication).
  </Accordion>
  <Accordion title="Multiple subdomains authenticated (acme, beta); specify --subdomain.">
    **Problem**: more than one workspace is signed in, so the target is ambiguous. <br />
    **Solution**: add `--subdomain <name>` to the command. For `logout`, `--all` signs out of every workspace.
  </Accordion>
  <Accordion title='Not authenticated for "foo". Authenticated subdomains: acme, beta.'>
    **Problem**: the `--subdomain` value does not match any signed-in workspace. <br />
    **Solution**: use one of the listed subdomains, or [sign in](/cli/authentication) to the new one.
  </Accordion>
  <Accordion title="Subdomain not found. Please check that you entered the correct subdomain.">
    **Problem**: `neetoplaydash login` could not find a workspace at `<subdomain>.neetoplaydash.com`. <br />
    **Solution**: use the first part of your workspace URL. For `https://spinkart.neetoplaydash.com`, enter `spinkart`.
  </Accordion>
  <Accordion title="Authentication session expired. Please try again.">
    **Problem**: the browser sign-in was not approved before the session expired. `NeetoPlaydash CLI authentication timed out after 5 minutes. Please try again.` means the CLI stopped waiting. <br />
    **Solution**: run `neetoplaydash login` again and approve the sign-in in the browser. If the browser does not open, visit the URL the CLI prints.
  </Accordion>
  <Accordion title="Could not connect to NeetoPlaydash. Check your internet connection">
    **Problem**: the CLI could not reach the API. <br />
    **Solution**: check your network and run `neetoplaydash doctor`. If [`NEETOPLAYDASH_BASE_URL`](/cli/authentication#environment-variables) is set, confirm it points at a reachable server.
  </Accordion>
  <Accordion title='required flag(s) "xxx" not set'>
    **Problem**: a required flag was omitted. <br />
    **Solution**: check the command's [reference page](/cli-reference/overview) or run `neetoplaydash <command> --help` for the required flags.
  </Accordion>
  <Accordion title='Flag --project cannot be blank. / Argument "run_id" cannot be blank.'>
    **Problem**: a required flag or positional argument was passed as an empty string, usually from an unset shell variable. <br />
    **Solution**: check that the variable holds the id you expect.
  </Accordion>
  <Accordion title="API error (422): <message>">
    **Problem**: the server rejected the request. The CLI prints `API error (<status>): <message>`, one line per additional error, and a `Suggestion:` line for common statuses: 401 (sign in again), 403 (no permission), 404 (check the ID), 422 (check required fields with `--help`), and 429 (rate limited, wait and retry). <br />
    **Solution**: follow the suggestion. For 401, run `neetoplaydash login` to refresh the session.
  </Accordion>
  <Accordion title="API error (400): Invalid date range format">
    **Problem**: `insights show` received a `--start-date` or `--end-date` that is not `YYYY-MM-DD`. When `--start-date` is older than the most recent 3 months, the message is `Insights are available only for the most recent 3 months` with the earliest date you can use. <br />
    **Solution**: pass dates as `YYYY-MM-DD`, with `--start-date` inside the most recent 3 months.
  </Accordion>
  <Accordion title="A command returns fewer results than the dashboard shows">
    **Problem**: list commands are paginated and return one page by default. <br />
    **Solution**: raise `--page-size` (max 50 for `projects list` and `runs list`, 100 for `test-entities list`) or walk the pages with `--page`. See [Pagination](/cli/output-formats#pagination).
  </Accordion>
  <Accordion title="A test entity id is refused for a run you know it ran in">
    **Problem**: a test entity id must name an entity that the given run recorded. An entity that ran only in other runs is refused. <br />
    **Solution**: confirm the id with `neetoplaydash test-entities list <run_id> --project <project_id>`.
  </Accordion>
  <Accordion title="Claude Code not found (~/.claude/ does not exist).">
    **Problem**: `neetoplaydash setup claude` requires Claude Code to have been run at least once. <br />
    **Solution**: install and open Claude Code, then run the command again.
  </Accordion>
</AccordionGroup>

## Check the version

```bash
neetoplaydash version
```

Prints the CLI version, commit hash, and build date - useful when reporting an issue. To upgrade, run [`neetoplaydash update`](/cli-reference/utility#update).
