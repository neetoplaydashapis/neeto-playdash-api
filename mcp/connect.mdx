title: "Connect"
description: "Point your AI assistant at the NeetoPlaydash MCP server."
---

NeetoPlaydash hosts the MCP server, so there is nothing to install or run locally. Add the endpoint to your assistant's MCP configuration, authenticate, and the NeetoPlaydash tools become available.

## Server details

| | |
| --- | --- |
| **Endpoint** | `https://connect.neetoplaydash.com/mcp/messages` |
| **Transport** | HTTP |
| **Authentication** | OAuth 2.1, or an API key as a bearer token |
| **Scopes** | `read`, `offline_access` |

## Which method your client supports

| Client | OAuth | API key |
| --- | --- | --- |
| Claude (web, desktop, Cowork) | Yes | - |
| ChatGPT | Yes | - |
| Claude Code | Yes | Yes |
| Codex | Yes | Yes |
| Cursor | Yes | Yes |
| Gemini CLI | Yes | Yes |
| VS Code | Yes | Yes |
| Windsurf | Yes | Yes |

For the clients that read a config file, the credential's presence is what selects the method: leave the `headers` block out and the client falls back to OAuth when the server challenges it. Read [Authentication](/mcp/authentication) before choosing - the two reach different things.

## Connect with OAuth

<Tabs>
  <Tab title="Claude">
    NeetoPlaydash is not listed in Anthropic's connector directory, so you add it yourself as a custom connector.

    Open **[Settings → Connectors](https://claude.ai/customize/connectors)**, click **Add**, then **Add custom connector**.

    <Frame caption="The Add menu in Claude's Connectors settings.">
      <img src="/assets/mcp/claude-add-menu.png" alt="Menu under the Add button in Claude's Connectors settings, with two items, Browse connectors and Add custom connector" />
    </Frame>

    Give it a **Name** such as `NeetoPlaydash`, paste the URL, and click **Add**:

    ```
    https://connect.neetoplaydash.com/mcp/messages
    ```

    Leave **Advanced settings** alone. The optional OAuth client ID and secret there are for servers that cannot register a client on their own, and NeetoPlaydash registers each client automatically.

    <Frame caption="The Add custom connector dialog, ready to submit.">
      <img src="/assets/mcp/claude-add-custom-connector-dialog.png" alt="Claude's 'Add custom connector' dialog with the name NeetoPlaydash and the server URL https://connect.neetoplaydash.com/mcp/messages filled in, and empty optional OAuth client ID and secret fields under Advanced settings" />
    </Frame>

    Then click **Connect** on the new entry. Claude opens NeetoPlaydash in your browser to sign in and approve the workspaces.

    One connector list backs claude.ai, the Claude desktop app, Claude mobile, and Cowork, so a connector you add in one shows up in the others.

    On a Team plan you may not be able to add it yourself. An Owner adds the same server URL once under **[Organization settings → Connectors](https://claude.ai/admin-settings/connectors)** - the approval covers that one connector rather than custom connectors as a whole - after which everyone connects it from their own Connectors list.

    Anthropic documents the current steps in [Get started with custom connectors using remote MCP](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).
  </Tab>
  <Tab title="ChatGPT">
    Turn on developer mode first: **Settings → Security and login → Developer mode**. The **Plugins** settings section links straight to it.

    <Frame caption="Developer mode is what lets ChatGPT add an MCP server of its own.">
      <img src="/assets/mcp/chatgpt-developer-mode.png" alt="ChatGPT's Developer mode setting, tagged Elevated risk, with its toggle switched on" />
    </Frame>

    Then open **Plugins → Browse plugins → + → New Plugin**, enter a name, set **Connection** to **Server URL**, and paste the URL:

    ```
    https://connect.neetoplaydash.com/mcp/messages
    ```

    Leave **Authentication** on **OAuth** - ChatGPT reads NeetoPlaydash's OAuth settings from the URL, so **Advanced OAuth settings** needs nothing from you. Tick **I understand and want to continue**, click **Create**, and approve the sign in.

    OpenAI documents the current steps in [Building MCP servers for plugins and API integrations](https://developers.openai.com/api/docs/mcp). They renamed the app directory to the plugin directory in July 2026, so older walkthroughs may say "apps" or "connectors" where the UI now says "plugins".
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http neetoplaydash https://connect.neetoplaydash.com/mcp/messages
    ```

    Then run `/mcp` inside Claude Code and pick **neetoplaydash** to sign in. Omitting `--header` is what makes this an OAuth connection.
  </Tab>
  <Tab title="Codex">
    Add the server to `~/.codex/config.toml`:

    ```toml
    [mcp_servers.neetoplaydash]
    url = "https://connect.neetoplaydash.com/mcp/messages"
    ```

    Then sign in:

    ```bash
    codex mcp login neetoplaydash
    ```

    `auth` defaults to `oauth`, so it does not need to be set. Note that this file is TOML, not JSON.
  </Tab>
  <Tab title="Cursor">
    Create or edit `~/.cursor/mcp.json`:

    ```json
    {
      "mcpServers": {
        "neetoplaydash": {
          "url": "https://connect.neetoplaydash.com/mcp/messages"
        }
      }
    }
    ```

    Save the file, then restart Cursor or reload its window. Cursor prompts you to sign in the first time it connects. The remote server shape has no `type` field.
  </Tab>
  <Tab title="Gemini CLI">
    Add the server to `~/.gemini/settings.json`:

    ```json
    {
      "mcpServers": {
        "neetoplaydash": {
          "httpUrl": "https://connect.neetoplaydash.com/mcp/messages"
        }
      }
    }
    ```

    Use `httpUrl`, not `url` - `url` means SSE in Gemini CLI. The CLI discovers the OAuth configuration from the server and opens a browser on the first 401. Run `/mcp auth neetoplaydash` to manage it afterwards.
  </Tab>
  <Tab title="VS Code">
    Create `.vscode/mcp.json` in your workspace:

    ```json
    {
      "servers": {
        "neetoplaydash": {
          "type": "http",
          "url": "https://connect.neetoplaydash.com/mcp/messages"
        }
      }
    }
    ```

    VS Code prompts you to sign in when it first connects. This requires VS Code 1.99 or later and Copilot Chat's **Agent** mode. VS Code uses `servers`, not `mcpServers`.
  </Tab>
  <Tab title="Windsurf">
    Edit `~/.codeium/windsurf/mcp_config.json`:

    ```json
    {
      "mcpServers": {
        "neetoplaydash": {
          "serverUrl": "https://connect.neetoplaydash.com/mcp/messages"
        }
      }
    }
    ```

    Windsurf uses `serverUrl`, not `url`. Enable the server in **Settings → Cascade → MCP Servers** and sign in when prompted.
  </Tab>
</Tabs>

### What the sign in looks like

Whichever client you started from, NeetoPlaydash runs the same steps in your browser.

<Steps>
  <Step title="Name your workspace">
    Enter the subdomain of the workspace you want the assistant to read. For `acme.neetoplaydash.com`, enter `acme`. See [Workspace subdomain](/getting-started/workspace-subdomain).

    <Frame caption="The first screen of the NeetoPlaydash OAuth flow.">
      <img src="/assets/mcp/oauth-connect-workspace.png" alt="NeetoPlaydash dialog headed 'Connect your workspace' with a workspace subdomain field, a fixed .neetoplaydash.com suffix, and a Continue button" />
    </Frame>
  </Step>
  <Step title="Sign in">
    Sign in to that workspace if you are not signed in already.
  </Step>
  <Step title="Check what you are approving">
    **Authorize access** names the workspace, the email you signed in as, and the host the client sends you back to. Under **What this connection can do**, NeetoPlaydash asks for **Read** and **Stay connected**. Both are marked *always granted*, so both are ticked and disabled and there is nothing for you to choose. NeetoPlaydash advertises no write or delete permission for a client to ask for.

    **Workspaces to connect** appears only when your email belongs to more than one workspace. The one you signed in to is ticked and cannot be unticked; tick any others this connection may read.

    <Frame caption="The Authorize access screen, with both permissions always granted.">
      <img src="/assets/mcp/oauth-authorize.png" alt="NeetoPlaydash 'Authorize access' screen showing the workspace, the signed-in email, the host it sends you back to, a 'What this connection can do' fieldset listing Read and Stay connected as ticked, disabled, always granted rows, a 'Workspaces to connect' list, and Cancel and Authorize buttons" />
    </Frame>
  </Step>
  <Step title="Authorize">
    Click **Authorize**. The browser returns you to the client, which stores the token and lists the NeetoPlaydash tools.
  </Step>
</Steps>

## Connect with an API key

Replace `YOUR_API_KEY` with your [NeetoPlaydash API key](/mcp/authentication) in each snippet below.

<Tabs>
  <Tab title="Claude Code">
    Add the server to `~/.claude.json`:

    ```json
    {
      "mcpServers": {
        "neetoplaydash": {
          "type": "http",
          "url": "https://connect.neetoplaydash.com/mcp/messages",
          "headers": {
            "Authorization": "Bearer YOUR_API_KEY"
          }
        }
      }
    }
    ```

    Save the file, then restart Claude Code.
  </Tab>
  <Tab title="Codex">
    Put the key in an environment variable, then name that variable in `~/.codex/config.toml`:

    ```toml
    [mcp_servers.neetoplaydash]
    url = "https://connect.neetoplaydash.com/mcp/messages"
    bearer_token_env_var = "NEETOPLAYDASH_API_KEY"
    ```

    `bearer_token_env_var` takes the **name** of the environment variable, not the key itself.
  </Tab>
  <Tab title="Cursor">
    Create or edit `~/.cursor/mcp.json`:

    ```json
    {
      "mcpServers": {
        "neetoplaydash": {
          "url": "https://connect.neetoplaydash.com/mcp/messages",
          "headers": {
            "Authorization": "Bearer YOUR_API_KEY"
          }
        }
      }
    }
    ```

    Save the file, then restart Cursor or reload its window.
  </Tab>
  <Tab title="Gemini CLI">
    Add the server to `~/.gemini/settings.json`:

    ```json
    {
      "mcpServers": {
        "neetoplaydash": {
          "httpUrl": "https://connect.neetoplaydash.com/mcp/messages",
          "headers": {
            "Authorization": "Bearer YOUR_API_KEY"
          }
        }
      }
    }
    ```

    Use `httpUrl`, not `url` - `url` means SSE in Gemini CLI.
  </Tab>
  <Tab title="VS Code">
    Create `.vscode/mcp.json` in your workspace:

    ```json
    {
      "servers": {
        "neetoplaydash": {
          "type": "http",
          "url": "https://connect.neetoplaydash.com/mcp/messages",
          "headers": {
            "Authorization": "Bearer YOUR_API_KEY"
          }
        }
      }
    }
    ```

    <Warning>
      `.vscode/mcp.json` lives in your repository. Do not commit an API key - use
      VS Code's input variables, or connect with OAuth instead.
    </Warning>

    This requires VS Code 1.99 or later and Copilot Chat's **Agent** mode. VS Code uses `servers`, not `mcpServers`.
  </Tab>
  <Tab title="Windsurf">
    Edit `~/.codeium/windsurf/mcp_config.json`:

    ```json
    {
      "mcpServers": {
        "neetoplaydash": {
          "serverUrl": "https://connect.neetoplaydash.com/mcp/messages",
          "headers": {
            "Authorization": "Bearer YOUR_API_KEY"
          }
        }
      }
    }
    ```

    Windsurf uses `serverUrl`, not `url`. Enable the server in **Settings → Cascade → MCP Servers**. Cascade allows up to 100 tools across every connected server, so turn a few others off if it complains.
  </Tab>
</Tabs>

## Verify the connection

After your assistant reloads, confirm `neetoplaydash` is listed among its tools. Then try a prompt such as *"List my NeetoPlaydash projects."* Find more in [Examples](/mcp/examples).

If it does not appear, see [Troubleshooting](/mcp/troubleshooting).
