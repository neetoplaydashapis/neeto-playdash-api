A run is one execution of a project's Playwright suite, reported by CI. Runs carry the commit, branch, author, tags, and status, plus the aggregate pass/fail counts. For fields and response details, see the [API reference](/api/runs/list).

## List runs

This command lists the runs recorded for a project, newest first. Use this when you start triage: filter to the branch and the status you are chasing.

```bash
neetoplaydash runs list pdqmxlz --branch main --status failed
```

**Required arguments:**

- `<project_id>` - the project whose runs to list, from [`projects list`](/cli-reference/projects).

<RunsListFlags />

`--status` takes exactly one of `running`, `passed`, `failed`, `passing`, `failing`, `timedOut`, `interrupted`.

The server caps this endpoint at 50 records per page. A larger `--page-size` prints a warning on standard error, and the server clamps the page to 50. Check `pagination.page_size` in the response for the size actually applied.

Every run the project holds is listed, including one that reported no test attempts at all. Such a run still carries its commit, branch, and status, but its `run_statistics` is empty and `test-entities list` reports nothing for it.

## Show a run

This command shows one run with its summary, aggregate statistics, and the spec files it executed, each with the tests grouped under it. Use this when you want the shape of a whole run in a single call rather than paging through its test entities. `get` is still accepted as an alias for `show`.

```bash
neetoplaydash runs show kftwnab --project pdqmxlz
```

**Required arguments:**

- `<run_id>` - the run to show, from [`runs list`](#list-runs).
- `--project <project_id>` - the project the run belongs to.
