A project is the top of the resource tree: it owns the runs, which own the test entities. Every other command takes a project id, and `projects list` is where you get one. For fields and response details, see the [API reference](/api/projects/list).

## List projects

This command lists every project in the workspace, newest first. Use this when you want to find the `project_id` that the `runs`, `test-entities`, `traces`, `top-errors`, and `result-histories` commands need.

```bash
neetoplaydash projects list
```

The server caps this endpoint at 50 records per page. A larger `--page-size` prints a warning on standard error, and the server clamps the page to 50. Check `pagination.page_size` in the response for the size actually applied.

```json Sample output (--json)
{
  "data": [
    {
      "id": "pdqmxlz",
      "name": "Spinkart Web",
      "archived": false
    },
    {
      "id": "zmqhcvt",
      "name": "Spinkart Admin",
      "archived": true
    }
  ],
  "breadcrumbs": [
    { "label": "List runs", "command": "neetoplaydash runs list <project_id>" }
  ],
  "pagination": {
    "total_records": 2,
    "total_pages": 1,
    "current_page_number": 1,
    "page_size": 15
  }
}
```

Archived projects are listed alongside active ones and are marked by the `archived` flag.
